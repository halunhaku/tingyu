## 5. 与目标图的差异，逐条

渲染见 [`index.html`](../screenshots/ui-a1/index.html)。以下每条都注明了是「按规格」还是「以代码为准」（设计文档 §1.2 的原则）。

1. **氛围的位置**：目标图把封面氛围铺到整页（曲库深色右下有一层粉光），实现里氛围只画在外壳底层、透过侧栏玻璃显出来（§10-1 把「30% 封面氛围」写在侧栏名下；§4.4 又说「不得叠浅色透明层」，页面是不透明 Canvas）。按规格实现，与静帧的差别是**页面上没有那层彩色**。
2. **侧栏「资料库」眉题**：§10-1 写「三组（资料库/来源/歌单）带 11/600 分组眉题与计数」，静帧里第一组没有眉题（曲库直接跟在搜索框后）。以静帧为准：来源、歌单有 11/600 眉题与计数，资料库组的计数落在「曲库 201」「收藏 N」两行上。
3. **弹层的遮罩**：MyGo 的 `Modal` 把遮罩写死为 40% 黑，深色规格要 56%。改用 `ui.DialogBase`（同一条模态/焦点/Esc 机制，遮罩颜色由调用方给），面板用 Regular 玻璃。**这一条属于「无法用 MyGo 现成 API 做到」**：`ui.Modal` 的遮罩不可配置，替代方案如上，已实现。同理，若沿用 `Modal` 自带的不透明面板，Regular 玻璃只会在面板背后模糊自己，等于没做——所以换成了 `DialogBase`。
4. **加载骨架**：骨架条（8 高、圆角 4、Shimmer 1400 ms）已实现在 `components.Skeleton`，但它只在列首屏加载时出现，而 `tools/uipreview` 会先等到 `Settled()` 再取帧，所以**对比页里没有骨架截图**。骨架由代码路径保证（`TrackTable` 之前的分支），未做像素证据。
5. **行菜单入口**：§10-4 的固定列宽最后两列是「时长 56 + 收藏 30」，没有「更多（•••）」列。因此 ••• 删除，菜单改由**右键**打开（§11 要求保留的正是右键菜单）。这是一处**可见入口消失**，如果要求保留 •••，需要把列宽规格改成 …/56/30/30 并重新出图。
6. **传输条多一个「打开播放舞台」按钮**：静帧右侧只有队列/歌词/音量；实现保留了 `二段上箭头`（舞台入口），因为 §11 的「能力不丢失」没有把它列进可牺牲项，而删掉它会让鼠标用户失去舞台入口。
7. **传输条少一个收藏心形**：静帧左侧曲名旁有一个心形；写死的规格（§10-3）只要求「48 封面 + 13/500 曲名」，且行内已有收藏，故未加。
8. **曲库工具栏多「添加目录…」、少 ⌘F 键帽**：前者是既有能力（§11 未列入可牺牲项），后者是自绘搜索框里叠键帽的额外工作；搜索框在 <1000 DIP 时隐藏（900 最小窗口放不下整行控件），此时侧栏搜索与 ⌘F 仍在。
9. **最小窗口的列退化**：固定列宽 862 DIP 在 900 宽窗口（表宽 600）放不下，规则是**整列让位**：先「专辑」，再「来源」，再「艺术家」，最后把「曲名」压到不小于 160。900×600 的实测见 `library-min-light.png`（曲名 + 时长两列，其余整列消失，不裁切行）。
10. **焦点环的触发**：MyGo 只暴露「整表是否键盘聚焦」（`List.FocusVisible`），没有「这一行是否键盘聚焦」，所以行环由行在**绘制期**自绘（2 px、Accent、内缩 2 DIP），并关掉 List 的整表环。副作用：**鼠标点进表格时也会显示行环**（键盘与指针无法在这里区分）。这是 §4.4「键盘焦点 2 px 环」的一处保真度让步，未假装区分。
11. **右栏文字**：静帧里封面卡艺术家是 11/500（numSm 带 tnum），实现用 11/400 普通数字——tnum 只用在时长与计数（§10-6 的原文）。
12. **版本行**：静帧是「0.1.0 · 内核数据」，实现仍是 `model.Version` 的「内核数据 · 0.5.0-dev」（改版本号不属于界面批次的决定）。

## 6. 真机窗口抽验（§13-2）：**未完成**

做了什么：

```bash
# 1) 用 pub-cache 里同一套 libmpv 0.36 + FFmpeg xcframework 组装（生产包路径）
cp -R ~/.pub-cache/hosted/pub.dev/media_kit_libs_macos_audio-1.1.4/macos/Frameworks/* \
      client/build/frameworks/
cd client && ./scripts/bundle.sh        # → build/darwin-arm64/听屿.app（14.0 MB，ad-hoc）
# 2) 只读副本启动，开帧日志
TINGYU_DATA_DIR=/tmp/tingyu-a1-data TINGYU_READ_ONLY=1 \
  MYGO_FRAME_STATS=all build/darwin-arm64/听屿.app/Contents/MacOS/听屿
```

得到的事实：

- 窗口创建成功：`CGWindowList` 读到 `听屿` 窗口 **1200×760**（默认尺寸，状态栏/托盘也正常）。
- 该帧**走 GPU 路径**：`drawn on the GPU: 220 instances in 33 batches … 16 batches awaiting specialized pipelines`（后者是玻璃着色器首次使用时的编译）。
- 启动日志无错误，`session: mygo.NowPlaying ready`、`tray: menu bar item ready`。

没做到的部分与原因：

- `screencapture -l <windowid>` 报 `could not create image from window`；整屏截图得到的是**锁屏界面**（`使用触控 ID 或输入密码`）。这台机器当前已锁屏，且本进程没有「屏幕录制」权限，TCC 不给权限就拿不到窗口像素。**没有任何真机窗口截图**，所以「玻璃在 Metal 上的实际观感」与「2 px 环在真机上的观感」**未验证**。
- 离屏渲染不能替代：`ui.Tester`/`ui.Render` 走软件光栅，玻璃是另一套像素实现（Metal 着色器 vs CPU 采样），观感会有差别；焦点环倒是同一段 `Painter.FocusRing`，理论上一致，但也只有离屏证据。

补救建议（一条命令，解锁后即可）：`cd client && ./scripts/bundle.sh && TINGYU_DATA_DIR=<副本> build/darwin-arm64/听屿.app/Contents/MacOS/听屿`，然后截图对比 `docs/screenshots/ui-a1/library-*.png`。若允许给终端「屏幕录制」权限，我可以直接补这一张图。
