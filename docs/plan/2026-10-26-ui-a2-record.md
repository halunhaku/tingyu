## 5. 与目标图的差异，逐条

渲染见 [`index.html`](../screenshots/ui-a2/index.html)。每条注明是“按规格”“以代码为准”（设计文档 §1.2）还是“静帧没画状态”。

**舞台**

1. **舞台页头**：静帧左上是返回箭头（无按钮底）、右上是心/放大镜/×。实现同结构，并把 MyGo 按钮的底与边框设成透明——否则默认按钮在浅色下是一块白方，深色下是一块浅方（第一版的渲染图里能看到）。
2. **歌词窗口的行数**：静帧固定 8 行（当前行前 3 后 4）；实现同样取 `current-3 .. +4`，不足 8 行时显示已有行；歌词不可用时给一句“这首歌没有歌词；可按 ⌘L 打开歌词页。”
3. **“接下来 共 N 首”的 N**：静帧是整条队列长度（24）。实现用 `len(queue)`（含当前曲），行只列 `index+1` 起的 3 首；队列为空时写“队列里没有下一首了。”
4. **静帧没有音量滑杆、没有队列/歌词按钮**：实现照删（⌘↑/⌘↓、⌘U、⌘L 与传输条上的按钮仍在，见 §8）。
5. **播放失败**：静帧没有失败状态。实现保留曲名下的“播放失败：…”与“重试此曲”（§11 的失败文案不能丢）。
6. **封面尺寸随窗口高度收缩**：1200×760 取 392（与静帧一致）；900×600 取 240，内容才装得下（`stage-min-light.png`）。
7. **舞台的“正在播放”眉题**：静帧 11/600/+0.8；实现用 `tokens.Overline` 同值，但不再显示内核状态句（“正在缓冲”等），状态改由播放按钮与失败行表达。

**来源**

8. **页头返回键删除**：静帧的来源/设置页没有返回箭头（侧栏常驻就是导航）。实现把 `s.Back` 从这两页去掉；`⌘4`/`⌘,` 与侧栏仍直达。
9. **卡片宽度**：卡片按可用宽度伸展（1200 宽 → 580，静帧 570），信息栏定宽 288（静帧 288）。
10. **“夸克网盘（直链播放，登录凭据在系统钥匙串）”一行**：静帧省略。实现保留在操作行下面——它回答“这个来源怎么播”的问题，且信息栏与它是同一句话的两种粒度。
11. **操作行**：立即同步（主按钮）/ 查看曲目 / `•••`（菜单里是“删除来源…”）；凭据失效时多一个“重新登录”。静帧的 `•••` 里没有写内容，这里放删除，是因为 §4.3 把销毁性动作列在“更多”里。
12. **900 宽**：信息栏移到卡片下方（静帧只给 1200），否则卡片被压到 280 宽，同步结果只剩省略号（`sources-min-light.png`）。
13. **页头内边距**：实现的 `Page()` 是 16/32，静帧是 32/36（第一批统一的口径，本批不改，避免动其他页面）。

**设置**

14. **页头返回键删除**：同来源页。
15. **关于卡**：静帧宽 237，实现 240（240 = 900 − 620 − 40）；内容按静帧：版本、一句话、播放内核 / 媒体会话 / 数据规模。
16. **“关于”页签**：右侧本来就是关于卡，所以关于页签改为整宽显示同一张卡，不再在右边重复一张。
17. **其余四个分区（音乐库/元数据/来源/数据）没有目标静帧**：用同一套卡片、20/20 行距、`Stat` 统计节奏重排；说明文字改成用户口径（不再出现 Flutter 版、M5 管线、settings.json、TINGYU_* 变量、schema 版本）。七个分区都出了图（`settings-section-0..6-light.png`）。
18. **版本号**：静帧写 0.1.0；实现把 `model.Version` 从 `内核数据 · 0.5.0-dev` 改为 `0.1.0`（与 `mygo.json` 一致）。这是收尾 1 的“清掉开发字样”，不是另起版本号。
19. **页头到标签的间距**：实现沿用 `Page()` 的 10 DIP，静帧 14；同 §5-13 的口径差。

**收尾**

20. **“资料库”眉题的计数**：§10-1 写“三组带眉题与计数”。实现只给眉题、不给计数：同一组里“曲库 201”“收藏 N”已经各带 tnum 计数，再在眉题上写 201 会让一个组出现两个同样的数。这是本批唯一与 §10-1 字面不同的地方，取静帧与信息重复度的折中。
21. **页脚规则**：`Pager` 与 `LoadMore` 各只有一套文案（未加载完：进度 + 按钮/“正在加载…”；加载完：单句）。第一批那种“已显示 x/y”和“已全部加载”同屏的情况没有了。

## 6. 真机抽验（§13-2）：**未完成，未取得真机图**

做了什么：

```bash
# 1) 生产包路径组装（pub-cache 里同一套 libmpv 0.36 + FFmpeg）
cp -R ~/.pub-cache/hosted/pub.dev/media_kit_libs_macos_audio-1.1.4/macos/Frameworks/* \
      client/build/frameworks/
cd client && FRAMEWORK_SRC="$PWD/build/frameworks" ./scripts/bundle.sh
# 2) 只读副本启动，开帧日志
TINGYU_DATA_DIR=/tmp/tingyu-a2-data TINGYU_READ_ONLY=1 MYGO_FRAME_STATS=all \
  ./build/darwin-arm64/听屿.app/Contents/MacOS/听屿
```

得到的事实：

- 窗口创建成功，1200×760、最小 900×600；启动日志 `startup ready` 正常，`session: mygo.NowPlaying ready`、`tray: menu bar item ready`。
- 第一帧**走 GPU 路径**：`frame 1 took 281.6 ms … present 264.1 (drawn on the GPU: 209 instances in 34 batches (3 opaque; … image 0), 0 ops culled, … 2 batches awaiting specialized pipelines)`（后者是玻璃着色器首次编译）。
- 窗口在 `CGWindowList` 里可见（id 22845，owner 听屿，1200×760）。

没做到的部分与原因：

- `CGSSessionScreenIsLocked = Yes`（2026-10-26 23:45 检查）。`screencapture -x` 整屏得到 **纯黑**（所有像素 0,0,0）。
- `screencapture -x -l 22845` 报 `could not create image from window`；进程也**没有“屏幕录制”权限**（TCC 不给就取不到窗口像素）。CoreGraphics 的 `CGWindowListCreateImage` 在 macOS 15 起已废弃，无法作为替代。
- 所以**没有任何真机窗口截图**：玻璃在 Metal 上的实际观感、舞台全窗氛围在真机上的亮度、2 px 焦点环的真机观感，本批都**未验证**。离屏渲染走软件光栅，不是同一条像素路径，不能冒充真机。

解锁后补图（一条命令 + 截图）：

```bash

TINGYU_DATA_DIR=/tmp/tingyu-a2-data TINGYU_READ_ONLY=1 \

# 窗口图：⌘⇧5（或 /usr/sbin/screencapture -x -l<windowid> <out.png>）
```

（`/tmp/listwin.swift` 是本次用来列窗口 id 的十行脚本：`CGWindowListCopyWindowInfo` → 打印 owner/name/id/bounds。）

## 7. 帧时间

**10,000 行滚动**（`TestLibraryScrollP95At10000Rows`，400 步 × 1200 DIP、等页口径、离屏软件光栅，与第一批同口径同机器）：

| 版本 | p50 | p95 | p99 | max |
|---|---|---|---|---|
| 第一批（记录 §4） | 4.20 ms | **7.29 ms** | 7.51 ms | — |
| 本批 | 4.19 ms | **7.28 ms** | 7.79 ms | 12.03 ms |

**玻璃**：本批没改侧栏/传输条的玻璃，第一批记录的离屏成本（约 5.5 ms/帧）不变；滚动 p95 与第一批一致，没有新的掉帧来源。

**舞台新增的全窗氛围**（`TestStageFrameBudget`，1200×760 离屏，冷帧 = 新开窗口画第一帧，稳态 = 帧保留后重画）：

| 主题 | 冷帧 p95 | 稳态 p95 |
|---|---|---|
| 浅色（有氛围） | 8.10 ms | 0.032 ms |
| 深色（有氛围） | 7.92 ms | 0.032 ms |
| 浅色（关掉取色，无氛围） | 2.57 ms | 0.029 ms |

结论：**冷帧里氛围约 5.5 ms（离屏软件光栅），与玻璃同一量级**；稳态几乎为零（帧保留，静态舞台不重画）。真机走 Metal 时这张 28 px 贴图 + 一次色调覆盖是一次全屏四边形与一次填充，成本远低于软件光栅，但**未在真机量测**（锁屏）。真机若出现掉帧，第一优先是把 `StageAmbientWash` 的覆盖改成对缩略图预乘（不再每帧混合），而不是去掉氛围。
