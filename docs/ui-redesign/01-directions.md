## 共同内容与跨端原则

- 使用虚构曲目；当前曲固定“海风经过 / 林间回声 / 潮汐手记”，播放态1:24 / 4:12，避免真实歌曲封面与歌词。元数据夹具见 [fixture.json](directions/fixture.json)，不导入用户数据库。
- 海平面/礁石、橙色窗景、蓝色群山、植物四组原创封面意象跨稿复用；生成参考传递造成构图/色调漂移，并非同一封面文件逐像素复用。选定后应提取统一资产、固定字体和严格数据，再建立可重复渲染稿。
- A采用“书架+列表→手机纯列表→歌词舞台”；B采用“专辑浏览→两列封面→沉浸歌词”；C采用“表格来源列→来源筛选列表→当前/接下来队列”。三套在相同核心任务上比较不同信息优先级，而非改业务能力。
- 搜索从侧栏拥挤小框提升为内容区完整入口；手机均有“来源”文字入口。最终点击路径、键盘焦点、错误恢复和加载态在P2细化，图稿不构成交互已完成的证据。
- 全屏播放替代外壳与迷你条；手机不展示桌面侧栏。队列明确区分当前曲与接下来；C主稿展示该分组，A/B通过队列入口进入。

## 三套明显不同的探索方向

以下色值、字体和尺寸是探索假设，不覆盖现有 `DESIGN.md` 或 Flutter token。三套均保持相同曲库数据、导航任务与播放能力，比较视觉品质和交互效率，避免靠不同内容掩盖差异。

| 维度 | A：静屿 · 编辑式曲库 | B：夜航 · 沉浸式聆听 | C：声档 · 精密音乐档案 |
|---|---|---|---|
| 体验重点 | 安静、易浏览、封面与文字平衡 | 封面情绪、播放连续性、夜间使用 | 大曲库检索、排序、来源可追溯 |
| 颜色候选 | 暖白#F8F7F3、墨色#202322、低饱和苔绿#426457；Dark为炭灰 | 深海蓝#101827、冷白#EFF3FA、青蓝#63CCD9；Light保持冷白 | 纸白#FAFAFC、石墨#18191D、琥珀#9A5D09；Dark保留清楚网格层级 |
| 排版 | 中文无衬线，较大标题与宽松行距；少量英文编辑标题可尝试衬线 | 无衬线中粗标题、清晰歌词层次；弱化非必要元数据 | 无衬线紧凑层级；时长/码率等数字等宽，中文不等宽 |
| 桌面曲库 | 清楚侧栏、精选封面区与可切换歌曲列表；不增加虚构推荐业务 | 可收拢导航，封面网格为主，底部持续播放条 | 侧栏+可排序表格+可选信息检查器；来源作为明确筛选维度 |
| 手机曲库 | 曲库分段+单列歌曲，封面留白，主标题优先 | 封面卡片与轻量迷你条；手势不是唯一入口 | 单列高效列表，筛选收进明确面板；固定搜索可达 |
| 桌面播放 | 大封面、曲目信息、歌词双栏；边界克制 | 封面衍生的受控背景、歌词为第二主角；保留静态背景设置 | 固定清楚的控制区，队列/歌词分栏，技术信息次级呈现 |
| 手机播放 | 封面与主控居中，歌词/队列用明确入口 | 封面到舞台的连续过渡，主控可单手触达 | 不依赖大幅动效，主控和队列操作位置稳定 |
| 组件差异 | 小到中圆角、细分隔、低阴影、文字按钮 | 大封面圆角、分层面板、低速动效、受限半透明 | 较小圆角、清晰列对齐/选中/焦点、高信息密度 |
| 主要风险 | 过多留白降低曲库效率 | 背景降低歌词对比度、动效性能成本 | 工具感过强、移动端拥挤 |

Apple Music、Spotify、Plexamp 仅作为后续研究对象：分别研究内容层级、持续播放与导航、个人曲库及沉浸播放模式。以上不是对其当前版本的事实描述；下一阶段需查阅官方资料/实际界面并记录访问日期与具体模式，不复制品牌资产、布局或专有图标。

## 原P1执行任务与验收（保留计划，完成度以上文为准）

1. **补齐P0关键证据**：重新构建固定补丁引擎Release，记录源码提交与产物哈希；修正采集调用为绝对路径；在独立数据目录准备固定曲目/来源夹具，避免使用用户库做基准。补无内容、加载、鉴权过期、同步失败/重试、有歌词、长标题、多条队列、添加来源弹窗。Android/iOS未接入前只标记“手机视口”，禁止标为真机。
2. **研究模式**：收集三款产品官方公开参考，各记录入口、导航、曲库与舞台状态及适用边界，输出链接与日期。确定听屿需要保留的来源管理特色。
3. **固定比较内容**：同一12首测试音轨，包含长中文/英文/混排、无封面、多艺术家、长专辑名；同一封面资产、同一播放时刻。视觉稿尺寸统一桌面1440×900、手机390×844，并注明逻辑像素。
4. **制作12张主稿**：每方向4张＝桌面曲库、桌面播放、手机曲库、手机播放。保存 `directions/{a,b,c}/{desktop-library,desktop-player,mobile-library,mobile-player}.png`；保留可编辑源文件。另附Light/Dark配色与关键组件对照，不能用文字表格替代视觉稿。
5. **设计审查**：逐图检查层级、字号、长文案、封面比例、触控、焦点、错误恢复与跨屏导航一致性；输出图名+位置+类型+严重性+修复要求。没有具体问题不返工，连续自动返工最多两轮；仍不通过则停止并说明原因。
6. **用户选择门禁**：展示三方向的同屏对比及取舍，等待用户明确选择或指定组合。选前不提交主题/页面改版；选择后记录批准日期、图稿版本与允许调整范围，再进入P2。

Golden环境必须锁定Flutter/Dart、操作系统、字体文件及哈希、locale、DPR、视口、固定时间和数据，禁用网络与随机动效；字体选择及许可需记录。现有Windows基准可继续校验，但不能自动成为新批准基准。更新仅在用户明确批准相应视觉改动后执行，提交前同时审阅旧图、新图和差异图。普通CI仍跳过Golden时，必须有独立固定环境视觉任务。

A07凭据回退失败应单独安排修复与权限验证，不与视觉重构合并。跨平台清单至少覆盖Windows补丁引擎、Android后台播放/SAF/系统返回、iOS安全区/授权、macOS快捷键/媒体会话、Linux播放/MPRIS；未实际执行就保持“待验”。
