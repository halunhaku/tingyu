# 三份设计文档独立审查（1）

审查范围：`docs/UI_UX_AUDIT.md`、`docs/UX_REDESIGN.md`、`DESIGN.md`，与既有 `app/lib`、`app/test` 和 CI 配置对照。方法：只读代码/文档逐项核查；未运行应用、测试或构建。以下路径和行号均相对于仓库根目录；`[推断]` 表示由代码结构推出的风险，`[未验证]` 表示缺少本次实际测量。审查期间其他协作者可能并行修改仓库，本报告的“现状”以本次读取到的上述文件内容为准。

## 1. 结论摘要

**暂不可按现有文档直接进入 Phase 4 实施；P0 阻断项 3 项。** 核心原因是要求实现的队列编辑、真正“从曲库移除”和逐文件同步失败回执，分别与明确禁止改动的播放、数据和来源接口相冲突：`docs/UX_REDESIGN.md:164-166,178-180,214-215,322-327`；现有能力分别见 `app/lib/app/playback_controller.dart:18-37,392-455`、`app/lib/data/repositories/track_repository.dart:218-227`、`app/lib/sources/source_adapter.dart:4-31`。先明确允许的**向后兼容接口扩展**、用户数据语义及回归约束，再形成可实施的迁移计划。其余路由/断点/主题组件架构原则上可由 Flutter + Riverpod 3 + go_router 18 实现，不能把“可采用单 ShellRoute”误写为“自动保留每个页面的局部状态”：`app/pubspec.yaml:24-28`、`app/lib/app/router.dart:24-33`、`docs/UX_REDESIGN.md:104-122`。

## 2. 问题清单（按严重度）

### P0 阻断

**P0-1　播放队列操作与冻结的内核契约矛盾。** 证据：`docs/UX_REDESIGN.md:143-147,164-166,214-215,322-327` 要求“下一首播放”插队、末尾追加、移除、清空、重排；`app/lib/app/playback_controller.dart:18-37,59-79,200-222,329-389,392-455` 将展示队列、已解析条目、索引映射和预取指针并行维护；`app/lib/playback/tingyu_audio_handler.dart:69-97` 与 `app/lib/playback/playback_engine.dart:31-45` 只提供替换整个队列、尾部追加，且 audio_service 队列需同步发布；审计又明确禁止改控制器/播放内核 `docs/UI_UX_AUDIT.md:60-67`。影响：直接在 UI 改列表会使高亮、下一首、随机/循环、预取、系统媒体（Windows SMTC/锁屏）的曲目索引不一致；整体重装引擎会打断正在播放的流，尤其是 `TrackResolver` 为 Quark 换直链并保留鉴权头的路径（`app/lib/app/track_resolver.dart:15-42`、`app/lib/app/source_adapters.dart:63-83`）。**修正**：把队列编辑明确列为允许修改 `PlaybackController`、`TingyuAudioHandler` 及必要引擎接口的有界例外；定义来源队列/已解析队列/系统媒体队列的原子更新规则、正在播放项不可误删、重复曲目按位置而非 id 处理、预取 generation 隔离、直链不被重新获取的策略；为两种引擎、循环/随机、播放中插队/删除及系统媒体队列增加行为断言。未明确这些契约前，不应把菜单操作列为可交付能力。

**P0-2　“从库中移除”会误删用户资产或在再次扫描后复活。** 证据：批量栏和右键菜单要求“从库中移除”并确认 `docs/UX_REDESIGN.md:164-166`，同时坚持不改数据/schema `docs/UX_REDESIGN.md:322-327`；`TrackRepository` 已有收藏、富化和 `mergeScan` 等方法，但没有面向“从库移除”的单曲目操作 `app/lib/data/repositories/track_repository.dart:77-87,218-267`；完整扫描以缺失路径作为删除依据 `app/lib/data/repositories/track_repository.dart:247-267`，删曲目还会级联移除歌单引用 `app/lib/data/db/schema.dart:126-142`；老库导入保留曲目与歌单 id `app/lib/data/legacy_import.dart:34-39,113-175`。影响：仅删除 SQLite 行会在下一次扫描重新入库；若删除源文件或整来源则可能造成不可逆的数据损失；误删歌单引用、收藏、歌词会破坏业务。**修正**：明确“移除”是排除扫描、删除库记录还是删除实体文件及撤销窗口；为“排除扫描”增加持久标记/表并升数据库 schemaVersion、迁移既有库及 legacy 导入结果，或在文档中明确选择其他可实施的持久语义，同时增补仓库公开操作、确认文本和重复扫描/恢复/歌单级联回归。不能把歌单的“移除条目”冒充“从库中移除”。

**P0-3　同步失败明细的既定协议没有所需数据。** 证据：要求“失败 z（可展开文件名与原因）” `docs/UX_REDESIGN.md:178-180`，却同时禁止修改来源适配/同步协议 `docs/UX_REDESIGN.md:322-327`；`SourceScanResult` 仅含 `tracks/skipped/cancelled/truncated/truncationReason`，没有逐文件失败记录 `app/lib/sources/source_adapter.dart:4-32`；`SourceSyncController` 只有扫描计数、最终合并数，整体异常只剩一个消息 `app/lib/features/sources/source_sync.dart:12-32,48-116,193-206`。影响：无法从“跳过 3 项”可靠还原 3 个文件名和错误原因，伪造明细违反“真实状态”原则；丢失 `isAuthoritative` 判定又会让残缺扫描删除收藏/歌单引用（`app/lib/sources/source_adapter.dart:22-31`、`app/lib/data/repositories/track_repository.dart:218-220`）。**修正**：明确允许 `SourceScanResult` 增加每项错误的结构化诊断（原路径、异常类别、可展示原因），逐个来源实现、保证取消/截断仍为非权威快照；同步回执区分扫描跳过、合并新增/更新/删除和整体异常并给已有状态保留的回归测试。不能从当前 `skipped` 数字推测明细。

### P1 必须修

**P1-1　路由身份、旧路径迁移与页面状态保持缺少闭环。** 证据：新路径 `/album/:id`、`/artist/:id`、`/settings/:section`，旧路径直接删除 `docs/UX_REDESIGN.md:104-122`；现有 ArtistSummary 用 `name`、AlbumSummary 用 `(artist,album)`，没有对应 id `app/lib/data/models/library_summaries.dart:3-28`；旧路由在 `app/lib/app/router.dart:24-87`，macOS 菜单仍跳旧路径 `app/lib/main.dart:236-283`，测试锁定“根 Tab 不压栈、详情可 pop” `app/test/navigation_gesture_test.dart:130-170`。设计称单 `ShellRoute` + provider 不用 `StatefulShellRoute` `docs/UX_REDESIGN.md:104-106`，但当前侧栏搜索的 `TextEditingController` 和页面滚动/焦点等是局部状态 `app/lib/features/shell/app_shell.dart:16-24,108-115`。影响：[推断] 切换路径/重建外壳时仅查询结果可由 provider 恢复，滚动位置、选区、焦点和返回目标未被保证；旧菜单和调试路由可能进入 404。**修正**：先定聚合详情的稳定、可转义复合键，或者明确新增 id 的数据库迁移；建立旧路径→新路径全部调用方/菜单/测试/入口映射；以 `go` 切根页、`push` 切详情，显式保存会话级排序/滚动/选择状态并验证 resize 后和系统返回的历史。无需为了保活强行换 StatefulShellRoute，但需要行为证据。

**P1-2　独立舞台的 Navigator 与交互返回语义未定义。** 证据：`/stage` 无外壳、`/queue` 和 `/lyrics` 又为无外壳独立页 `docs/UX_REDESIGN.md:118-120`；浏览态右检查器、移动舞台手势、Hero 展开 `docs/UX_REDESIGN.md:171-174`；现有迷你条以 `push('/now-playing')` 入场、现播放页本地布尔值切面板且宽度阈值 720 `app/lib/features/player/mini_player.dart:46-49`、`app/lib/features/player/now_playing_page.dart:28-59,135-157`。影响：[推断] 用 `go('/stage')` 会失去从详情页回来的路由栈；挂错 Navigator 会使 Hero / 弹层 / Esc 返回跨栈不稳定；舞台无外壳后，歌词/队列与浏览态检查器需要共享状态和入口。**修正**：声明根 Navigator key、ShellRoute navigator key 和 `/stage` 的 `parentNavigatorKey`/push-pop 契约；定义无历史深链的安全回退、`?tab=` 同步、舞台与检查器共用的 provider 状态；为 compact/medium 的队列、歌词按钮到抽屉/独立页的动作各写一条页面规格，并核验 Hero 在跨 Navigator 上的实际效果。

**P1-3　同步取消与并发边界在体验方案中悬空。** 证据：首次扫描/重试/同步进度要求 `docs/UX_REDESIGN.md:176-180,220-225`；适配器支持 `isCancelled`，且非权威扫描禁止删除 `app/lib/sources/source_adapter.dart:22-31,42-52`；当前控制器调用 `adapter.scan(onProgress:...)` 并未传取消谓词，同一来源只靠 `running` 防重复、后台 `unawaited(enrichSource())` `app/lib/features/sources/source_sync.dart:42-96,107-158`；仓库只在完整扫描 `removeMissing` 时删除曲目 `app/lib/data/repositories/track_repository.dart:218-267`。影响：[推断] 新增取消按钮但不贯穿适配器会出现“取消后仍入库/覆盖新一次同步”的错乱；补全和同步并发可能覆盖最终回执。**修正**：在 UI 控制器建立每来源取消令牌/操作 generation，传入已有 `isCancelled`，序列化同步与富化，旧任务回调不得覆盖新任务；取消后按 `scan.isAuthoritative == false` 合并已发现条目并保留未见曲目；为同时点两次、扫描中退出/删来源和中途取消加实测回归。

**P1-4　动态封面取色不能“直接复用已有 24×24 解码”。** 证据：规范要求 24×24 复用、按路径+mtime+尺寸缓存、isolate 提取 `DESIGN.md:134-145`；现有 `CoverArt` 只把文件交给 `Image.file(cacheWidth=size×DPR)`、远端交给 `CachedNetworkImage(memCacheWidth/maxWidthDiskCache=size×DPR)`，没有可消费的 RGBA 缩略像素 `app/lib/features/shared/cover_art.dart:9-14,38-56,76-91`；`coverFileProvider` 只是异步查文件 `app/lib/app/providers.dart:45-52`，`CoverStore` 的相对文件名按图片内容命名 `app/lib/data/cover_store.dart:12-33,81-98`。影响：[推断] 再读原图/网络下载造成内存和网络开销；用本地 mtime 当远端 URL 缓存键无效；快速换曲后旧取色结果可能涂到新封面；没有封面时本应直接中性渐变。**修正**：明确独立的低分辨率解码/像素取得路径（先输出至多 24×24 RGBA，才送 `compute`），复用同一图片缓存或字节源，分别定义本地内容文件名和远端 URL/版本的键、无封面/失败回退与“只接收当前曲目结果”的防竞态策略；给快速切歌、缺封面、网络超时和重复封面加入性能/正确性验收。不得把“已有 cacheWidth”当成已取得可统计像素。
